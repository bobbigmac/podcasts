### assistant

Canonical handling is in place on both server and client.

**SSR (`build_site.py`)**
- Every page gets a `<link rel="canonical">` (absolute when `url` / `AP_SITE_URL` is set, otherwise the path-only href)
- `AP_SITE_URL` is written into `site.json` so the client can build the same URLs
- Fixed `_abs_site_href` so you don’t get doubled paths like `/podcasts/podcasts/…`

**Client (`util/canonical.js`)**
- Keeps canonical + `og:url` on the clean page URL (no `?e=`)
- On episode deep links, adds `<meta name="robots" content="noindex, follow">` while canonical still points at the podcast page
- Runs on load, SPA navigation, and when the URL query changes

**Already in place from the sitemap work**
- `robots.txt` with `Disallow: /*?e=`

For production, set either `url: https://bobdavies.co.uk/podcasts` in the feeds site config or the `AP_SITE_URL` repo variable in GitHub Actions. Without that, SSR canonicals are path-only and Google may not treat them as strongly.

After deploy, use Search Console URL inspection on a `?e=` URL — it should show canonical `https://bobdavies.co.uk/podcasts/{slug}/` with no query string.
